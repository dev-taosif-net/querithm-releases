Built for daily database work

One fast native workspace across six engines, with zero telemetry and full offline support.

Six database engines

SQL Server, PostgreSQL, MySQL / MariaDB and Oracle Database (TCPS by default) over direct TLS or SSH tunnels, plus local SQLite and DuckDB files (read-only until you allow writes) or in-memory tabs.

Two-tier AST autocomplete

Dialect-aware Monaco editor for T-SQL, PostgreSQL, MySQL, Oracle SQL & PL/SQL, SQLite and DuckDB. Frequency-ranked suggestions, CTE & temp-table columns, parameter hints, Find usages and Rename.

1M-row grid & notebooks

Streaming Apache Arrow grid with inline editing, tabbed, stacked or side-by-side result sets, CSV / JSON / XLSX import & export, charts, cell viewer and .sqlbook notebooks.

Plans, compare & monitoring

Visual execution plans (estimated on every engine; actual on SQL Server, PostgreSQL, DuckDB and Oracle), schema & data compare, Activity Monitor, SQL Server Trace and PostgreSQL step debugger.

Production safety & groups

Organize servers into connection groups with color-coded Dev / Staging / Prod environments. Engine-enforced production & destructive-statement guards keep mistakes out of Prod.

Offline-first & private

Fonts, editor, grid and plan renderer are bundled. Passwords and SSH keys stay in your OS keyring, and signed in-app updates keep Querithm current (optional in Settings).

First launch & verification

The installers are not code-signed yet, so your OS will ask you to confirm once.

Windows: “Windows protected your PC”

Click More info, then Run anyway.

macOS: “Querithm can’t be opened”
  1. Open the .dmg and drag Querithm to Applications.
  2. Open Querithm once and close the warning.
  3. Go to System Settings → Privacy & Security, scroll down and click Open Anyway.

If macOS says the app “is damaged”, run this in Terminal, then open it again:

xattr -dr com.apple.quarantine /Applications/Querithm.app
Linux: AppImage and packages 
chmod +x Querithm-linux-x64.AppImage
./Querithm-linux-x64.AppImage

sudo apt install ./Querithm-linux-x64.deb   # Debian / Ubuntu
sudo dnf install ./Querithm-linux-x64.rpm   # Fedora / RHEL
Verify your download (SHA-256)

Every release has a SHA256SUMS.txt. Compare it with:

sha256sum Querithm-*                     # Linux
shasum -a 256 Querithm-*                 # macOS
Get-FileHash .\Querithm-windows-x64-setup.exe   # Windows PowerShell

Frequently asked questions

Quick answers about supported databases, offline privacy, licensing, and performance.

What databases does Querithm support?

Querithm supports six database engines in one native workspace: Microsoft SQL Server, PostgreSQL, MySQL / MariaDB, Oracle Database (over TCPS by default), SQLite, and DuckDB, with direct TLS and SSH tunnel connections plus local file and in-memory tabs.

Is Querithm free and offline-first?

Yes. Querithm is free to download under the GNU GPL-3.0 license, requires no account, collects zero telemetry, and runs fully offline. Fonts, the Monaco SQL editor, the Apache Arrow grid, and the execution plan renderer are all bundled locally.

Which operating systems does Querithm run on?

Querithm runs natively on Windows 10 and 11 (64-bit .exe installer and .msi package), macOS (Apple Silicon and Intel .dmg), and Linux x86-64 (AppImage, Debian/Ubuntu .deb, and Fedora/RHEL .rpm). On macOS, Oracle Database connections require Apple Silicon.

How does Querithm protect database passwords and production environments?

Database passwords and SSH keys are stored strictly in your operating system keyring and never leave your machine. Connection groups let you color-code Dev, Staging, and Prod servers with engine-enforced production and destructive-statement guards.

How fast is Querithm on large SQL files and million-row results?

On benchmarked SQL Server 2022 and PostgreSQL 16 workloads (600 tables, 400 stored procedures, a 12,023-line procedure, and a 1M-row query), Querithm achieves 5.9 ms p95 typing latency, 37.4 ms p95 AST autocomplete, 229 ms to paint the first Apache Arrow batch, and 1.25 s cold start.
